# jev-search

## ローカル検索をすぐ試す

順位づけを改善した体験用CLIは **`search-local`**。APIキー不要、外部通信なし。

```sh
cd /path/to/jev-search
./search-local
```

起動後は自然な文章を入力する。`:1`、`:2`、`:3` で用意した検索例を試せる。

| 入力 | 動作 |
| --- | --- |
| 自然言語の文章 + Enter | 上位8件、パス、一致した語を表示 |
| `:1` | キーボードで表を編集するツールを探す例 |
| `:2` | 音楽を止めて音声入力するツールを探す例 |
| `:3` | RaycastとSpotlightの比較調査を探す例 |
| `p 2` | 2番目のファイルの関連箇所を表示 |
| `o 2` | 2番目のファイルを既定アプリで開く |
| `f 2` | 2番目のファイルをFinderで表示 |
| `:q` / Ctrl+C | 終了 |

```sh
# 1回だけ検索する
./search-local 'キーを押してしゃべると文字が入って、音楽も止めてくれるやつの使い方'
# 別のディレクトリを指定（このroot専用の索引を作成）
./search-local --root /path/to/documents '調べたい内容'
# ファイルを追加・編集したら、索引を更新して対話検索
./search-local --rebuild
# 機械処理用。標準エラーに準備情報、標準出力にJSON
./search-local '調べたい内容' --json --limit 5
```

既定の範囲はhome内の `src` のGit追跡ファイル、Downloads、マイドライブ、iCloudの文書領域。
Node.jsと `/opt/homebrew/bin/rg` を使う。追加のnpmインストールは不要。
最初に最大64KiB/ファイルのUTF-8本文から索引を作り、`.jev-cache/` に圧縮して保存する。
索引にはローカルのパス・見出し・単語と頻度が含まれる。Git対象外、ファイル権限600。
ファイルを更新しても自動再索引はしない。結果の更新検知表示と `--rebuild` を使う。
PDF・Office抽出、オンライン専用ファイルの網羅、本文64KiBより後ろの検索は未対応。

英語の単語境界、日本語の1文字語、見出し/本文/パス別のBM25型採点、複数語の一致率、
完全一致する本文の重複除外、小さな日英同義語辞書を使う。汎用の意味検索モデルは未使用。
結果の点数は関連度の相対値であり、正解確率ではない。
Jev評価用の候補選択も共有エンジンに実装したが、このCLIではAPI評価を実行しない。
Raycastの **Search Local Files** でも同じ順位づけと検索例を利用できる。

検証方法と限界: [ローカル検証](raycast/benchmarks/README.md)。

## 従来のJev API CLI

自然言語で指定ディレクトリ配下のテキストを再帰検索し、Jev の合致確率順に fzf で選択する試作 CLI。
Python 3.10 以降、ripgrep、fzf 0.74.3 以降を使用する。追加の Python パッケージは不要。

```sh
git clone https://github.com/kazuhideoki/jev-search.git
cd jev-search
./jev_search '通信失敗時の再試行を実装している' /path/to/search --dry-run
cp .env.example .env
# .env の TYPESAFE_API_KEY をエディターで設定
./jev_search '通信失敗時の再試行を実装している' /path/to/search
```

ghq を使う場合は `ghq get kazuhideoki/jev-search` でも取得できる。
実行ファイル名は `jev_search`。

`.env` はこの CLI と同じディレクトリから読み込む。検索対象の `.env` は読み込まない。
別の設定ファイルは `--env-file /path/to/config.env` で指定できる。
環境変数が `.env` より優先される。シェル展開や変数補間は行わない。
`.env` は Git の対象外。API キーをチャットやコマンド引数へ貼り付ける必要はない。

| 設定 | 初期値 | 意味 |
| --- | --- | --- |
| `TYPESAFE_API_KEY` | なし | TypeSafe 直接 API のキー |
| `JEV_CONCURRENCY` | `4` | 同時リクエスト数（1〜64） |
| `JEV_BATCH_TARGET_TOKENS` | `24000` | 推定入力トークン予算（1024〜28000） |

`--dry-run` は API キー不要で、通信しない。ファイル数、分割後の部分数、リクエスト別のファイル数・推定トークン数・推定費用を表示する。
ASCII 約3文字/token、非ASCII 約1文字/token としてリクエストの JSON 全体を推定する。
Jev の公式トークナイザーによる計数ではないため、実際の使用量や上限内への収まりは保証しない。
入力上限で HTTP 422 が発生する場合は `JEV_BATCH_TARGET_TOKENS` を小さくして再実行する。
実行後は応答の `usage.input_tokens` を集計し、推定との比較に使える。
料金の計算値は 2026-09-17 時点の入力 $0.042/100万トークン、出力無料。

対象は UTF-8 の通常ファイル。`.gitignore`、`.ignore` など ripgrep の除外設定を尊重する。
`RIPGREP_CONFIG_PATH` のオプションは適用しない。
Git リポジトリ外でも `.gitignore` を尊重する。隠しファイル、`.git`、`node_modules`、`.env*`、
指定した設定ファイル、シンボリックリンク、バイナリ、空ファイル、読み取れないファイルを除外する。
列挙前に除外したファイルは dry-run の除外数には含まれない。
PDF・画像・Office 文書からのテキスト抽出は行わない。対象の本文は TypeSafe API へ送信する。

大きなファイルは一部が重なるよう分割し、全体を評価する。ファイルの表示値は各部分の合致確率の最大値。
この値はファイル全体の校正済み確率ではなく、長いファイルが有利になる可能性もある。
評価中や一部分の失敗時には暫定値が表示され、ヘッダーに成功・失敗・未評価部分数を示す。
認証エラーでは未送信リクエストを打ち切り、「打ち切り」と表示する。
JSON にも全体数・成功数・失敗数・未評価数と終了状態を含める。
失敗や未評価を 0% として扱わない。

fzf の一覧は約0.2秒ごとに更新する。矢印キーで選択し、入力でファイル名を絞り込む。
検索文は起動時に固定する。プレビューは先頭300行。Enter で絶対パスを標準出力へ返す。
Esc で終了する。送信済みの HTTP リクエストは取り消せず、終了まで最大30秒程度待つ場合がある。
途中終了では送信済みリクエストの使用量を集計できない場合がある。
HTTP 429・529 と一部のサーバーエラーは指数バックオフで最大4回試行する。
失敗した部分がある場合は終了コード1。失敗応答や再試行の課金は取得できた使用量に含まれない。
結果・本文の永続キャッシュは作らず、検索ごとに評価する。ファイル一覧と本文はメモリに保持する。

```sh
# fzf を使わず確率順の JSON を返す
./jev_search '通信失敗時の再試行' /path/to/search --json

# API を使わない検証
python3 -m unittest discover -s . -p 'test_*.py' -v
```

仕様の根拠: [TypeSafe API](https://docs.typesafe.ai/api)、
[複数質問と入力予算](https://docs.typesafe.ai/primitives)、
[料金](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、
[fzf](https://github.com/junegunn/fzf)。

## Raycastのローカル検索

リポジトリのルートで以下を実行し、拡張をローカル登録する。

```sh
npm ci --prefix raycast
npm run build --prefix raycast
```

Raycastで **Search Local Files** を起動する。APIキー・検索ディレクトリの設定は不要。
srcのGit追跡ファイル、Downloads、マイドライブ、iCloudの文書を検索する。
初回に索引を作成し、以後はRaycastの拡張サポート領域に保存した索引を読み込む。
CLIの索引とは別保存だが、順位づけと検索範囲は共通。
ファイルを追加・変更したら `⌘⇧R` で索引を更新する。
このコマンドはAPIキーを使用せず、外部送信しない。
Raycastの100MBメモリ上限を避けるため、索引処理は専用のNodeプロセスで行い、
画面には上位100件と選択した抜粋のみを渡す。Node.jsは自動検出し、必要なら
コマンド設定の **Node.js Path** で指定できる。

| 操作 | 動作 |
| --- | --- |
| 検索例を選んでEnter | CLIと同じ3つの実例を検索 |
| 検索欄に文章を入力 | 150ms静止後にローカル索引を検索 |
| ↑ / ↓ | 候補の選択 |
| Enter | 選択したファイルを開く |
| ⌘⇧D | 関連箇所の抜粋を表示・非表示 |
| ⌘C | 絶対パスをコピー |
| ⌘⇧R | ファイル一覧と本文索引を更新 |
| Actions → Show in Finder | Finderでファイルの場所を表示 |

初回索引作成中も検索文を入力でき、準備後に検索する。
更新中に閉じた場合は以前の索引を維持する。初回にmacOSの権限等で読めない場所がある場合は、
読める文書の索引を作り、対象が一部であることとエラーを表示する。
更新時に新たな列挙エラーが発生した場合は、以前の索引を維持する。
読込除外・列挙エラーは検索例の画面にも表示する。索引形式の変更時は自動で再作成する。
PDF/Office未対応、先頭64KiBまで、隠しファイル等を除外する条件はCLIと同じ。
